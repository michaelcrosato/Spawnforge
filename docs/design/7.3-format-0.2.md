# Design: format 0.2

Milestone 7.3 of [plan 2](../plan-2.md), worked at max effort. This document settles how a
blueprint says everything plan 2 adds, before any of it is built. An independent review follows
it in [Review](#review), with each finding answered.

## Goals and constraints

- **One coherent language.** Plan 2's additions read like plan 1's fields: the same words for
  placement (`on`, `at`, `angle`, `side`), the same pattern for module slots (a limb's `foot`), and
  the same merge rules. A model that learnt 0.1 should guess most of 0.2.
- **Short blueprints.** Every new field has a default, and the common creature needs only a few
  words more than in 0.1: a dragon is a quadruped plus two wing limbs.
- **Strict and explicit.** Unknown keys stay errors. Friendly forms are explicit and normalized in
  their own step. Likely guesses (`body.heads`, `hand`, `motion.fly`) get hints that name the
  real field.
- **The core never names a module.** New behaviour arrives as modules (feet, membranes, parts,
  patterns, gaits, actions), with pack defaults and module fields carrying what the core needs.
- **Additive.** No 0.1 field changes meaning or name, so every 0.1 blueprint is a 0.2 blueprint
  once its `format` is relabelled. Later milestones extend the one 0.1 → 0.2 migration if they
  change a 0.1 field (8.3 rescales tooth sizes).
- **Validates before it is built.** The whole vocabulary validates now. What is not built yet
  validates, is skipped by compile, and warns `not_built` with the milestone that builds it.

## Decisions

### 1. Several heads: a count on the neck

```json
"body": { "neck": { "count": 3, "spread": 50, "length": 0.8 } }
```

- `count` (integer 1–9, default 1): necks, each carrying a head shaped like `body.head`, with the
  same jaw and the same parts. `spread` (0–180 degrees, default 40): the horizontal angle between
  the outermost necks, which fan out evenly from the front of the torso.
- **Why a count and not a list.** The scope table puts identical heads in plan 2 and different
  heads on one body in "Later". A list (`body.heads: [{ … }]`) would invite per-head fields that
  plan 2 cannot build, and every list adds merge rules and `[id=…]` paths. A count is one number
  to write and to mutate; a later format can grow a list beside it.
- **Why on the neck.** One neck carries one head, and a hydra's count is really a count of necks.
  `body.head.count` and `body.heads` get hints that point here.
- **Instances.** With one neck nothing changes. With several, the necks, heads and jaws are
  numbered from the creature's left (+X) to its right: `neck.1`, `head.1`, `jaw.1`, … Parts on
  `head`, `jaw` or `neck` get one copy per head, with the head number before the side:
  `horns.2.L`. `on` may name one instance (`"on": "head.2"`) to put a part on that head only, as
  `"on": "foreleg.L"` does for limbs. The **main head** is the middle one (the left of the middle
  two for an even count). It answers to plain `head` in sockets and look targets, and `spine`
  runs through its neck.
- **Errors.** A neck of `length` 0 with `count` > 1 is a warning (`heads_overlap`) from 9.1, when
  the overlap can be measured.

### 2. Several and split tails: a count with a split point

```json
"body": { "tail": { "count": 2, "spread": 30, "split": 0 } }
```

- `count` (1–9, default 1), `spread` (0–180, default 30) and `split` (0 to 0.95, default 0): with
  `split` 0 the tails leave the torso separately (a two-tailed fox, a nine-tailed kitsune); with
  `split` 0.7 one tail forks 70% of the way along (a forked tip). Each branch has the full tail's
  shape (`radius`, `curl` and so on) from the fork on.
- Instances are numbered like heads (`tail.1`, …), and parts on `tail` get a copy per tail
  (`stinger.2`). `spine` runs into the main tail.

### 3. New limb roles: `wing`, `fin`, `tentacle`

```json
{ "id": "wing", "role": "wing", "attach": { "at": 0.15, "angle": 35 }, "length": 1.4 }
{ "id": "pectoral", "role": "fin", "attach": { "at": 0.2, "angle": 120 }, "length": 0.4 }
{ "id": "arm", "role": "tentacle", "attach": { "at": 1, "angle": 150 }, "length": 2, "segments": 12, "curl": 120 }
```

- Roles decide motion: legs carry the body, arms are free, wings fold at rest and beat in the
  air, fins steer and beat in water, tentacles are long spring chains that curl and reach. A
  role is a better switch than a module because the controller, analysis and defaults all branch
  on it, and plan 1 already branches on `leg` and `arm`.
- **`segments`**: 2–4 for legs, arms, wings and fins, as now; 2–16 for tentacles. The schema
  allows 2–16 and validation reports more than 4 on other roles, with the fix.
- **`curl`** (degrees, -360 to 360, default 0): a tentacle's rest curl, spread along it like a
  tail's. Only tentacles take it; on other roles it is an error with "remove it" as the fix.
- **Attachment.** Wings, fins and tentacles attach to the torso, neck or tail, like legs and
  arms. Tentacles may also attach to the head (a face of tentacles).
- **Mirroring.** Wings and fins come in mirrored pairs by default, like everything with
  `side: "both"`; a single tentacle on the midline uses `side: "center"`.

### 4. Membranes: a module slot on the limb, like `foot`

```json
{ "id": "wing", "role": "wing", "membrane": { "type": "membrane.bat", "fingers": 4 } }
```

- Wings and fins carry a surface, which is a module in a new part slot, `membrane`, set through
  the limb's `membrane` field exactly as a foot is set through `foot`: the module's parameters
  sit beside `type`, and `null` means none.
- Modules: `membrane.bat` (skin between finger bones, body and hind limb), `membrane.insect`
  (thin veined plates), `membrane.feather` (flight feathers on the wing bones), `membrane.case`
  (a beetle's hard wing case) and `membrane.fin` (rays with skin between them). One prefix keeps
  them together in the catalogue, as `foot.*` does.
- **Defaults by role**, from the pack: a wing gets `membrane.bat`, a fin `membrane.fin`; legs,
  arms and tentacles get none. So `{ "id": "wing", "role": "wing" }` is a bat-like wing.
- A flipper is a fin limb with `"membrane": null`: the limb itself is flat.
- `membrane` on a leg, arm or tentacle is an error with "remove it, or make the limb a wing or
  fin" as the fix.

### 5. Feet by role; hands stay in `foot`

- Pack defaults become per role: legs and arms get `foot.claw`, wings, fins and tentacles get
  none. The schema stops writing a default foot; validation fills it from the role.
- Hands and pincers are foot-slot modules (`hand.grasp`, `hand.pincer`) set in `foot`:
  `"foot": { "type": "hand.grasp" }`. A separate `hand` field would give each limb two ways to
  say the same thing. `hand` as a key gets a hint: put it in `foot`.

### 6. Stance

`limbs[].stance` (optional): `plantigrade` (on the whole sole: bears, people), `digitigrade` (on
the toes: dogs, cats, birds) or `unguligrade` (on the hoof tips: horses). Left out, the foot
module suggests one (a new optional `stance` field on foot-slot modules), and without a
suggestion the limb keeps today's pose. It is a limb field rather than a foot parameter because
it shapes the leg's rest pose and planting, which the core owns.

### 7. Muscle and the S-neck

- `body.muscle` (0–1, default 0.5): how muscled the body is; 0 stays close to plan 1's tubes.
  `limbs[].muscle` overrides it per limb. The default is not 0, because phase 8 exists to make
  the default creature look better, and 0.x lets the look change.
- `body.neck.curve` (-90 to 90 degrees, default 0): bends the neck into an S, forward at its base
  and back up below the head for positive values (a swan), the reverse for negative ones.

### 8. Heads: lips, tongue, brow

`body.head.lips` (0–1, default 0.3, the lips' thickness along the mouth cut), `body.head.tongue`
(`none`, `flat` or `forked`, default `flat`) and `body.head.brow` (0–1, default 0.2, a brow
ridge). They shape the skin and the inner mouth, which the core builds, so they are head fields;
hard pieces of the head (beaks, mandibles, antennae) are parts.

### 9. Coverings: a `region` slot

```json
{ "id": "quills", "type": "quills", "attach": { "on": "spine", "region": "back", "from": 0.3, "to": 0.9 }, "params": { "density": 0.6 } }
{ "id": "shell", "type": "shell", "attach": { "on": "torso", "region": "back" } }
```

- A new part slot, `region`, scatters or conforms a part over an area of skin: `on` (a section,
  `spine` or a limb), `region` (`back`, `belly`, `sides` or `all`), and optionally `from` and `to`
  along it. How many pieces, and how close, are the module's parameters (`density`), since quills
  and scutes need different ranges.
- `region` in `attach` is accepted only for region-slot parts, and region-slot parts need it (the
  module's default anchor supplies it when left out). Errors name the slot either way.
- The part names follow the scope table: `shell`, `armor.bands`, `quills` (region slot);
  `plates.row`, `sail`, `fin.dorsal` (row slot); `frill`, `hood`, `fin.tail`, `antenna` (surface
  slot); `beak`, `mandible` (mouth slot).

### 10. Fur and hide

`skin.material` gains `hide` (thick, creased) and `fur`. Fur's settings sit in
`skin.fur: { "length": 0.03, "density": 0.8 }` (length in torso lengths, density 0–1), which
only `fur` uses: with another material it is a warning. Fur is a base material because it
changes how the whole skin is drawn (shells), not a pattern on top.

### 11. Swimming and flying: `motion.media`

```json
"motion": { "media": ["land", "water"] }
```

- `motion.media` lists where the creature moves: `land`, `water` and `air`. Left out, it is
  what the body suggests: `land`, plus `air` with wings, and `water` instead of `land` for a body
  with fins and no legs (a fish). Swimming is opt-in for everything else, because most game
  creatures never need it and it adds clips to every export.
- Gait modules declare the medium they serve (a new `medium` field, default `land`) and the body
  features they need, as actions do. Default gaits are those that suit the body in each listed
  medium. `motion.gaits` still overrides the list.
- `air` without a wing limb is an error ("nothing to fly with: add a limb with role wing").
  `motion.fly`, `motion.swim` and `motion.flying` get hints pointing to `media`.
- Plan 2's cross-cutting design calls these "media"; the field keeps the word, and the docs gloss
  it as "where it moves".

### 12. Stubs and `not_built`

- Modules gain an optional `planned` field: the milestone that builds them (`"9.3"`). A planned
  module is the real module file (id, parameters, docs and example) without build hooks.
  Planned gaits and actions never join the defaults.
- Validation warns `not_built` for every planned module a blueprint uses, and for core fields
  set to something the pipeline does not draw yet (`neck.count` above 1, a wing limb, a stance,
  `skin.material: "fur"`, …). The message names the milestone; compile skips what it cannot
  build and reports the same warnings. The table of core features lives in one core file, and
  each milestone deletes its rows.
- Body plans need no flag: `octopod` and `centaur` work now (eight legs walk with `walk`, a
  centaur's arms sit on an upright neck), while `wyvern` and `fish` validate and render without
  their wings and fins until 9.3.

### 13. Format and migration

`format` becomes `spawnforge/0.2`. The 0.1 → 0.2 migration only relabels, because nothing in 0.1
changes meaning. The corpus test runs every saved 0.1 blueprint through it. 8.3 extends the step
to rescale tooth sizes.

## Alternatives considered

| Choice | Alternative | Why not |
| --- | --- | --- |
| Head count on the neck | `body.heads` list with per-head shapes | Different heads are out of scope; a list costs merge rules and paths |
| Limb roles for wings, fins, tentacles | Wing and fin as parts | They need bone chains, IK, folding and springs, which limbs already have; parts with bones arrive only in 9.4 |
| `membrane` slot on the limb | Membrane parameters on the limb itself | Bat, insect, feathered and fin surfaces have different parameters; modules keep the core out of it |
| `hand.*` in `foot` | A separate `hand` field | Two fields for one slot; the hint covers the guess |
| `motion.media` list | Booleans (`swims`, `flies`) | One list covers opt-in and opt-out, and maps onto `generate --requires` |
| Muscle default 0.5 | 0 (today's look) | Phase 8's goal is a better default creature |
| `region` attach field | Region as a module parameter | Placement belongs in `attach`, where every other placement lives |
